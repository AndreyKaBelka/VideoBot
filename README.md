# Video Downloader Bot
 
Telegram-бот для скачивания видео по ссылкам (TikTok, Instagram). Бот принимает ссылку, сохраняет её в историю и асинхронно обрабатывает через очередь задач, после чего присылает пользователю результат.
 
## Архитектура
 
Проект состоит из двух независимых бинарников, использующих общие пакеты `internal/`:
 
- **`cmd/bot`** — принимает сообщения от Telegram, сохраняет ссылки в БД, ставит задачи в очередь и отправляет пользователю финальный ответ. Вся коммуникация с Telegram API сосредоточена исключительно в этом процессе.
- **`cmd/worker`** — забирает задачи из очереди, скачивает видео через Selenium/браузер и публикует задачу на отправку ответа.
Взаимодействие между процессами построено на двух типах задач River:
 
| Job | Направление | Назначение |
|---|---|---|
| `ProcessMessageArgs` | bot → worker | Обработка входящей ссылки, скачивание видео |
| `SendReplyArgs` | worker → bot | Отправка результата пользователю через Telegram API |
 
Такое разделение гарантирует, что worker не имеет прямого доступа к Telegram API, а всё общение с пользователем остаётся в зоне ответственности `cmd/bot`.
 
### Слои и границы
 
Проект придерживается Clean Architecture:
 
- **service layer** — определяет интерфейсы (например, `TxManager`), не зависит от конкретных реализаций;
- **infra layer** — реализует эти интерфейсы (pgx-пул, Selenium-клиент и т.д.);
- **`main.go`** каждого бинарника — точка сборки зависимостей (explicit DI, без DI-фреймворков).
Пул соединений с БД и другие инфраструктурные детали не "протекают" в service-слой. Транзакции прокидываются через `context.Value`.
 
## Стек технологий
 
- **Язык:** Go
- **База данных:** PostgreSQL
- **Очередь задач:** [River](https://riverqueue.com/) (`riverpgxv5` driver)
- **Доступ к БД:** [pgx/v5](https://github.com/jackc/pgx) + pgxpool
- **Миграции:** [Goose](https://github.com/pressly/goose)
- **Браузерная автоматизация:** `tebeka/selenium` + `seleniarm/standalone-chromium` (ARM-native образ для скачивания видео по ссылкам)
 
## Инфраструктура и деплой
 
Проект рассчитан на запуск на Raspberry Pi (arm64, Raspberry Pi OS) под управлением Docker Compose:
 
- `restart: unless-stopped` для всех сервисов;
- лимиты ресурсов (CPU/RAM) для каждого контейнера — окружение Pi ограничено по памяти;
- ротация логов, чтобы не изнашивать SD-карту;
- `seleniarm/standalone-chromium` — ARM-совместимый образ для headless-браузера.
 
## Установка и запуск
 
```bash
# Клонировать репозиторий
git clone https://github.com/<username>/<repo>.git
cd <repo>
 
# Скопировать и заполнить переменные окружения
cp .env.example .env
 
# Запустить через Docker Compose
docker compose up -d
```
 
### Переменные окружения
 
| Переменная | Описание |
|---|---|
| `TELEGRAM_BOT_TOKEN` | Токен Telegram-бота |
